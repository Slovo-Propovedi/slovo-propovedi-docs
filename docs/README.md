# Документация Слова.Проповеди (docs service)

Папка `docs/` — **первоисточник знаний о проекте** для разработчиков и AI-агентов (opencode, Claude Code, Cursor). Цель — чтобы агент читал `docs/` перед реализацией и не исследовал кодовую базу повторно, экономя токены, и обновлял `docs/` при каждом изменении кода.

Проект: автономный Swagger UI + OpenAPI-спецификация для **API — Слово.Проповеди** — полностью статический nginx-контейнер, не зависящий от админ-бэкенда (нет Postgres, MinIO или контейнеров бэкенда). Стек, архитектура и команды — в [`AGENTS.md`](../AGENTS.md).

## Работа с документацией для агентов (ЖЁСТКИЕ правила)

Эти правила обязательны для любого агента, работающего над проектом.

1. **Перед реализацией фичи/фикса** агент ОБЯЗАН прочитать соответствующие документы:
   - архитектурное решение → `architecture.md`;
   - изменение CI/CD/деплоя → `ci-cd.md`;
   - новая зависимость → `decisions.md`;
   - изменение процесса (git, коммиты, релизы) → `conventions.md`.
   Если документ ещё не создан — прочитать код, затем создать/дополнить документ (см. правило 4).

2. **При изменении кода** агент ОБЯЗАН обновить затронутые документы `docs/` **в том же PR/коммите**. Изменение кода без обновления `docs/` считается неполным.

3. **Каждый срезанный угол** (TODO, hack, отложенное решение) → запись в `docs/debt.md` **в том же PR**. Формат записи:
   `- [ ] <что> — <где (пути файлов)> — <когда вернуться>`. Закрытая запись: `- [x] ...`.

4. **Новые зависимости** — только через запись в `docs/decisions.md` (секция Approved stack) с объяснением «почему». Агент НЕ добавляет зависимости вне этого списка без обсуждения.

5. **Если в `docs/` нет нужной информации** — добавить её, исследовав код, чтобы следующий агент не делал это повторно. Неполная документация — тоже долг: добавь запись в `debt.md`.

## Структура docs/

| Файл | Назначение |
|------|------------|
| [`README.md`](./README.md) | Карта документации и правила для агентов (этот файл) |

## Соглашения по ведению

- Язык — **русский**; технические термины (Swagger UI, OpenAPI, nginx, Docker, Forgejo Actions, Traefik, systemd, buildx) — английским как есть.
- Машино-проверяемые правила (валидация YAML в husky, `validate:openapi`) уже живут в коде — docs объясняют «почему», а не дублируют правила.
- Ссылки на код — конкретные пути (`scripts/vps-deploy.sh`), ссылки между документами — относительные.
- Не выдумывать факты: если факт неизвестен — посмотреть в коде или оставить пометку `<!-- TODO: уточнить -->` и записать в `debt.md`.
- Решения не стираются: отменённое решение помечается зачёркиванием с объяснением в `decisions.md` (секция Superseded).
- Подробнее о процессе ведения: [`conventions.md`](./conventions.md).

## Краткий контекст продукта

Сервис отдаёт документацию API через Swagger UI: `/` — интерактивная документация, `/openAPI.yaml` — сырая OpenAPI-спецификация. Деплой полностью автоматизирован через **Forgejo Actions**: push в `main` → CI валидирует `openAPI.yaml`; push тега `v*` → Release-workflow ждёт прохода CI, заливает исходники на VPS по `tar+ssh`, строит образ через `docker buildx` и поднимает `slovo-docs.service` (systemd + Traefik, TLS через Let's Encrypt). Подробности и долги — в [`debt.md`](./debt.md).
